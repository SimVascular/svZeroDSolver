The block type is read from bc_type. Valid values are the blocks of class BlockClass::boundary_condition or BlockClass::closed_loop, except ClosedLoopHeartAndPulmonary, which is configured under closed_loop_blocks (see create_closed_loop()). Currently these are:

CORONARY_VAR_RES OpenLoopCoronaryVarResBC
ClosedLoopRCR ClosedLoopRCRBC

Handle the creation of external coupling blocks and connections with other blocks.

An external coupling block is the boundary through which an external solver (e.g. a 3D solver such as svMultiPhysics) exchanges flow and pressure with the 0D model. Its type accepts the same values as bc_type (see create_boundary_conditions()), but use FLOW or PRESSURE: those are the blocks whose time series the coupling interface updates (update_block_params() in interface.cpp), and the error for an invalid type says so. Besides name, type, and values, each block has:

  • connected_block: the 0D block on the other side of the coupling block, given as a boundary condition's bc_name, a vessel's vessel_name, or ClosedLoopHeartAndPulmonary.
  • location: inlet or outlet, the side of connected_block the coupling block attaches to. With inlet, flow goes from the coupling block into connected_block; with outlet, from connected_block into the coupling block. The connection to ClosedLoopHeartAndPulmonary is made by create_closed_loop() instead.

Only some connected blocks are supported at each location. A connected block's type is its bc_type for a boundary condition, or BloodVessel for any vessel. These lists are hard-coded in the implementation (supported_types), so update both together:

  • inlet: RESISTANCE, RCR, IMPEDANCE, ClosedLoopRCR, CORONARY, ClosedLoopCoronaryLeft, ClosedLoopCoronaryRight, BloodVessel
  • outlet: ClosedLoopRCR, ClosedLoopHeartAndPulmonary, BloodVessel

An invalid type or location, an unknown connected_block, or an unsupported connected block type fails at load time with an error naming the coupling block.

◆ load_simulation_model()

void load_simulation_model ( const nlohmann::json & config,
Model & model )

Load the 0D block in the model from a configuration.

Every block is created from a type string, read from a key that depends on the configuration section the block is in:

Section Type key Valid values documented in
vessels zero_d_element_type create_vessels()
junctions junction_type create_junctions()
boundary_conditions bc_type create_boundary_conditions()
external_solver_coupling_blocks type create_external_coupling()
closed_loop_blocks closed_loop_type create_closed_loop()
valves type create_valves()
chambers type create_chambers()

Each loader checks its type key before creating the block. An invalid type fails at load time with an error that names the block, section, and key, and lists the valid values. The loaders derive those values from the block factory (Model::block_factory_map) filtered by BlockClass, so a newly registered block is accepted in the section that matches its class without changes to the loader code. Type strings are case-sensitive.

The type lists in the comments of the individual loaders are written out by hand as a reference and can fall behind the registered blocks; the list in the error message is authoritative.

External coupling blocks are created before boundary conditions, so bc_type values are validated first, while building the map of boundary condition types. Otherwise a misspelled bc_type on a boundary condition that a coupling block connects to would be reported as an unrelated coupling error.

Parameters
configThe json configuration
modelThe 0D model

◆ resolve_cardiac_cycle_period()

void resolve_cardiac_cycle_period ( Model & model,
const SimulationParameters & params )

Reconcile the cardiac cycle period between the model and parameters.

The period may be defined by a model block (e.g. a closed-loop block or a chamber) or by simulation_parameters.cardiac_period. This resolves model.cardiac_cycle_period from both sources, throws if the two disagree, and falls back to a default of 1.0 if neither defines it. Must be called by every entry point (solver and coupled interface) before blocks that depend on the period are used.

Parameters
modelThe 0D model
paramsSimulation parameters read from the configuration
